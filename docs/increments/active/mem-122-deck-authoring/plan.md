# MEM-122 plan — presentation authoring from a deck plan

- [x] **Template.** `interpreter/executor/memoryos_deck/`: `theme.py` (16:9 geometry, one type ramp, three palettes, vi/en labels), `measure.py` (deterministic text fitting), `plan.py` (strict plan validation and caps), `render.py` (slide builders, footers, appended sources slides), `inspect.py` (deck faults).
- [x] **HTML output.** `web.py` renders the same plan at the same inch coordinates as one self-contained HTML deck (inline CSS, pictures as data URIs, arrow-key navigation, `@page` printing to 960 x 540 pt). This is option D of the [HTML deck research](html-deck-research.md): the app owns the markup and the model writes none of it.
- [x] **CLIs.** `render_deck.py` → `/usr/local/bin/render-deck` (the output suffix picks `.pptx` or `.html`, and one call may write both) and `check_pptx.py` → `/usr/local/bin/check-pptx`, copied in the executor Dockerfile beside `check-docx`, with `memoryos_deck` installed into site-packages like `memoryos_charts`.
- [x] **Guidance.** `ChatPrompts.RUN_PYTHON_GUIDANCE` presentation lines: write a deck plan and render it, never place shapes; name a `.html` output when the deck is to be read in a browser; run `check-pptx` and fix what it reports; save a figure before putting it on an `image` slide; cite with `sources` and `cites`.
- [x] **Tests.** `test_office_stack.py`: a Vietnamese deck renders to both formats in one call, passes `check-pptx`, converts with LibreOffice, and the HTML is self-contained (same slide count, picture inlined, no external reference, `@page` rule); an over-cap, misspelled and unknown-type plan is refused with no file written; a hand-built deck's faults are named and only an unreadable file fails the command. `ChatWebPromptsTest` covers the guidance lines.
- [x] **Docs.** `docs/specs/chat.md` Presentations bullet with its HTML sub-bullet, `docs/tests/chat.md` rows, `AGENTS.md` active increment entry, roadmap MEM-122 promoted from candidate to in-progress and listed under Active. The [HTML deck research](html-deck-research.md) records why the model never writes the markup itself.
- [x] **Evidence (2026-09-22, outside the executor image).** Deck rendering: an 11-slide Vietnamese deck covering every slide type rendered to `.pptx` and `.html` in one call with no warnings, and `check-pptx` reported no issues. Refusals: seven 400-character bullets, an unknown field, an unknown slide type, a nine-item bullet list and a table too wide for 10 pt were each refused with exit 1, the slide named and no file written. Gate: a hand-built deck reported sub-10 pt type, text past its box, placeholder text, a shape off the slide, an empty slide and the missing `render-deck` marker, and exited 1 only for the file it could not read. Reading: LibreOffice Impress 25.2 in a throwaway container with the image's font set (Carlito, Caladea, DejaVu, Liberation, Noto) converted the deck and every page was read as an image — title, agenda, section, metrics, bullets, table, image, columns, quote, closing and sources; a 200 dpi pixel probe confirmed the full-bleed slides reach the page edge. Theme shape styles are stripped so LibreOffice and PowerPoint resolve the same fill and outline. HTML: Chromium measured no element outside any slide box at scale 1, `page.pdf({preferCSSPageSize:true})` produced 11 pages of 960 x 540 pt — the same page box as the `.pptx` conversion — and the file carries no external reference. `./gradlew :core:test --tests '*ChatWebPromptsTest*'` passed. Still open: the `test_office_stack.py` deck cases against the built executor image and one uninterrupted `./gradlew clean check`.
