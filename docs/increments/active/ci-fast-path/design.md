# Shorter CI for #957

The baseline has Gradle parallel execution, its build cache and three core test JVMs. The longest core and API jobs still run their entire module suites serially across classes or within a small set of forks. Split those suites across runners with Gradle's test class filters. Run the core classpath task once alongside the architecture suites. Use historical JUnit reports from run 45641361015 to group slow packages and give all other packages a catch-all shard.

Use Buildx Bake to solve API and worker targets in parallel and share the Dockerfile's Gradle stage. Keycloak has its own build context and smoke test, so it can run beside Bake. Publish the two unsmoked targets directly from BuildKit on main, check their revision and source labels by digest, and pass the same component references to the existing release job. Keycloak keeps its local image smoke and verified push.

Spring Boot's `.github/workflows/build-pull-request.yml` runs verification with separate main orchestration. Here the single CI workflow retains the required-check name and selects PR image jobs by inputs. Move the production-build browser fixture suite to main and dispatch, where it must pass even when the PR's tree already passed the dev-server browser shards. Increase dev-server shards so broad browser changes use more runners. The production-build fixtures also use two runners. A serial dispatch took 5:19 for that job, enough to become the staging critical path after shortening the backend image build.

A dispatch on the PR branch exercises the all-area build graph without writing releases or deploying. CI timings come from GitHub job timestamps. Push-only publication and staging remain part of post-merge verification.

The owner’s follow-up on #957 prioritizes removing repeated checks and shifting expensive integration suites to main. In the prior PR head, the API shards spent about 50 seconds each in their longest test phase and another 90 seconds preparing the Gradle graph and compiling through core and sources. The core catch-all carried two architecture scans and the retrieval shard carried the real OpenSearch container. Keep architecture and API contract coverage on PRs, group the API contract and migration suites separately, and defer the broad HTTP chat, real OpenSearch and staging telemetry suites. These test classes have a single owner across PR and main shards. A verified PR supplies just its own tests and main must pass its remaining shards before publication.
