## Decision approach

Keep the existing authorized FILE ingestion, canonical extraction artifact, current Document/chunks and provenance contracts. Do not change Search or Chat. Pinned RAGFlow research does not justify replacing this pipeline: DeepDoc's shipped OCR dictionary lacks core Vietnamese symbols, its ordinary PDF route retains all selected rendered pages, and its remote Docling adapter drops item/table provenance. MinerU's stated 16 GiB minimum exceeds the local Docker allocation. Select an explicit OCR backend inside Docling instead; never silently fall back or mark partial extraction as success.

Local Docker has four CPUs and about 8 GiB total VM capacity; the host initially had about 2.8 GiB free RAM. Existing PostgreSQL and OpenSearch containers must remain untouched. Initial SSH access could not reach Docker without interactive privilege elevation, so the corpus investigation used only an isolated, resource-bounded local OCR service and modified no remote service. The subsequent authorized trusted-VPN remote cutover above supersedes that local-only runtime choice, not its historical evidence or unresolved fidelity limits.

## OCR selection evidence

The same real Vietnamese page was converted successfully by EasyOCR `vi,en`, RapidOCR `vi` and Tesseract `vie,eng`. Tesseract retained Vietnamese names and prose most clearly; RapidOCR dropped many diacritics. The installed pinned image rejects RapidOCR `iso:vi`, despite newer upstream portable-language documentation, but accepts `vi`. Tesseract requires the additional pinned `tesseract-langpack-vie-4.1.0-3.el9` package, installed in a minimal derived image. Its financial-table pilot still contains recognition errors, including some digits and separators; financial values require comparison with source images.

The upstream-image/EasyOCR default remains unchanged. Operators explicitly select the derived Tesseract image, engine/languages and optional full-page OCR. Parser configuration records these choices and the actual image revision as diagnostic metadata; it is not an artifact compatibility check or retry-output lock. Canonical artifacts retain the `memoryos-extraction-v1` schema. Normalized text is rendered from ordered canonical text/table blocks, not Docling's text export, which embedded sixteen binary image data URIs in the initial full-document result.

A 40-page conversion exceeded the 3 GiB trial limit and exited 137; the bounded 5 GiB, four-CPU trial completed in 616.56 seconds. The first authorized 45-page Q2 run later exceeded the coordinated 900-second processing limit while repository verification competed for resources; no partial result was published. The final isolated corpus run completed all six reports and 260 page maps on the same final image; [per-report evidence](../../../tests/ingestion.md#tasco-scanned-pdf-corpus--2026-09-10) separates this pipeline result from financial fidelity.

On one source financial-table page, ordinary full-page Tesseract recovered 63/70 numeric cells digit-exactly (90.0%), versus 58/70 for regional OCR and 61/70 for `tessdata_best`. Increasing resolution or changing page segmentation did not improve that result: 300-dpi PSM 3 recovered 60/70 digit-exactly, 300-dpi PSM 6 recovered 53/70, and 400-dpi PSM 6 recovered 60/70. Full-page OCR is an explicit scan-focused choice, not the default for PDFs with trustworthy native text. Seven numeric cells still differed or were missing in the selected pilot, including total-row alignment problems; this single-page measurement is not corpus-wide accuracy or financial-audit acceptance.

The complete Q1 consolidated run confirms a material table-fidelity failure on PDF page 8 (printed page 6): the current-period total liabilities and equity is absent and the prior-period total is assigned to the current-period column. This is already present in the canonical table cell offsets, independently of any consumer UI. Period, consolidated scope and VND units remain recognizable, but financial-table accuracy is not accepted. Do not repair this by swapping columns or editing source-specific numbers in MemoryOS.

An isolated, identical 216-dpi Q2 page produced byte-identical Tesseract TSV with four and one OpenMP threads, taking 15.06 and 6.55 seconds respectively. A global one-thread trial completed the 44-page English consolidated report but also constrained table-model processing. The final optional image instead wraps only the Tesseract executable with `OMP_THREAD_LIMIT=1`; the upstream image default and model parallelism remain untouched. A real source-page smoke check observed the child limit of one, an uncapped parent OpenMP limit and four parent threads. The first 40-page authorized run on this scoped image completed ingestion in 468.66 seconds with all pages represented. Do not run resource-heavy repository gates concurrently with corpus timing.

Pinned research: [DeepDoc PDF route](https://github.com/infiniflow/ragflow/blob/c178cdd5b91c1c0adc2ee7c5451841565da59790/deepdoc/parser/pdf_parser.py), [DeepDoc OCR dictionary](https://huggingface.co/InfiniFlow/deepdoc/blob/9c7aa2c730d7a242d7f04cf6109a6a239aefc717/ocr.res), [RAGFlow Docling adapter](https://github.com/infiniflow/ragflow/blob/c178cdd5b91c1c0adc2ee7c5451841565da59790/deepdoc/parser/docling_parser.py).
