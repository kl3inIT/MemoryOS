# MEM-134 — External data gate, first slice

A provider already carries a data boundary (`llm_provider.data_boundary`, MEM-102), and
[chat-models](../../../specs/chat-models.md) promises that "enforcement belongs to the external data gate (MEM-134)".
Nothing enforces it yet: a confidential contract retrieved by Search goes to an external model like any other text.

This first slice is the smallest real path that keeps a confidential Source away from an external model, asks the
person once per conversation before anything goes out, and leaves a record. It is sized to be shown, not to cover
every surface: the Group policy and the other egress paths are later slices, listed at the end.

## Reference

- **Onyx** has none of this. It has no internal/external label on a provider, no sensitivity flag on a connector or a
  document, no PII step before the model, and no per-send consent. Its Group-to-provider scoping falls back to the
  default provider when a person is refused (`backend/onyx/llm/factory.py`), which is the wrong direction for a rule
  about keeping data inside. Its incognito mode asks the provider not to retain content; the content still leaves.
- **Glean, Microsoft Purview for Copilot, Google DLP for Gemini** anchor the rule on the content, not the person, and
  apply it server-side after retrieval and before the model call. Glean says it outright: *"Even if a user has
  permission to access the content, Glean Assistant and Agents respect the exclusion rule"*, and excluded content
  stays searchable — only the model is kept from it.
- None of them separates an internal model from an external one. That split is what lets a confidential Source still
  be used with AI, as long as the model runs inside.

## Decisions

**The rule belongs to the Source.** `connector_credential_pairs.model_boundary` is `ANY` (the default, today's
behaviour) or `INTERNAL_ONLY`. A Group rule cannot express this: a Source is read through a Group only when it is
`PRIVATE`. A `PUBLIC` Source has no Group, and a `SYNC` Source takes its readers from Google Drive or SharePoint, so a
rule on Groups would never touch a confidential contract synchronised from Drive. A Group rule would also withhold
the external model from the whole Group for every question, including the ones that touch nothing confidential.

**It is enforced where retrieval is scoped, not where citations are drawn.** `SearchTool` sends passage text to the
turn's model in its own selection and classification calls before any evidence reaches the answer. The Source is
therefore removed from `SourceSearchScope` for a turn whose provider is external, the same way an agent's Source
allowlist narrows it today. The Source stays searchable in Search and readable in full; it is only kept from an
external model.

**The search tool says what it withheld.** When a withheld Source would have answered, the tool tells the model how
many relevant Sources it could not use, and the answer says so. Counting runs the same index query against the
withheld Sources and reads only their ids; none of their text reaches the model.

**A conversation that used internal data stays internal.** Every turn sends the conversation's history. If an internal
model quoted a confidential contract, switching the same conversation to an external model would send that quote out.
The first time an `INTERNAL_ONLY` passage enters a turn, `chat_session.internal_data_used_at` is set, and from then on
an external model is refused for that conversation. The person starts a new conversation to use one.

**An external model asks once per conversation and provider.** Before the first turn that would go to an external
provider, the turn is refused with `CHAT_EXTERNAL_CONSENT_REQUIRED` naming the provider; nothing is persisted and
nothing is sent. Accepting records `chat_external_consent(session, provider)` and the turn is sent again. A different
external provider in the same conversation asks again; a new conversation or a branch asks again. There is no
"don't ask again": it would turn this into a silent allow that no administrator chose.

**The record is the product, not the click.** People dismiss a repeated prompt within seconds (70% click-through on
Chrome SSL warnings, Akhawe & Felt 2013), so the dialog does not prove anyone deliberated. What it proves is recorded:
`chat.external_consent` names who agreed to send to which provider, in which conversation, and when. The dialog's two
choices carry equal weight.

**Session naming follows the conversation.** A title generated by an external model from a conversation that used
internal data would leak the same text; such a conversation keeps its short title.

## Scope

In:
- the Source flag, its setting and its audit (`source.update`, change `MODEL_BOUNDARY`);
- the retrieval exclusion and the note the answer carries;
- the conversation lock, the consent and its audit (`chat.external_consent`);
- naming that respects the lock;
- the Source setting and the consent dialog in the web app.

Out, as later slices:
- the MemoryOS MCP endpoint ([MEM-114](../mem-114-public-mcp-server/design.md#data-leaving-the-tenant)): every
  passage it returns goes to the external client's provider, so it always counts as external. It reads through the
  Search path, which this slice does not narrow, so it needs its own removal of `INTERNAL_ONLY` Sources; until then its
  per-Tenant switch stays off in production once it holds organization data (the owner configured it on 2026-10-03,
  while production held none);
- a policy per Group (`ALLOW` / `ASK` / `BLOCK`); this slice asks everyone;
- read-aloud, image editing and Web search queries, whose providers carry no boundary yet;
- embeddings at ingestion, configured per deployment rather than in the catalog;
- labels per document rather than per Source, and synchronising sensitivity labels from Drive or SharePoint;
- Vietnamese PII masking: spaCy ships no Vietnamese pipeline, so Presidio cannot find Vietnamese names at all.

Known limits, stated rather than hidden: a file the person uploads into the conversation is not a Source and carries
no flag, and nothing stops a person copying confidential text into the composer. Microsoft documents the same limit
for files in prompts.

## Demonstration

It needs one provider labelled Internal. Self-hosted serving was removed on 2026-09-19 (MEM-66), so the demonstration
labels a provider Internal whose agreement excludes retention and training, as [chat-models](../../../specs/chat-models.md)
allows, or runs a local model for the occasion.
