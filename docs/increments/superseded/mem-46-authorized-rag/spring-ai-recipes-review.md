## 2. Phần nghiên cứu thêm, không đưa thành yêu cầu mới

**HyDE:** [HydeQueryTransformer](https://github.com/habuma/spring-ai-recipes/blob/f89baf57e83e2007fb0ccb96852252c1fa1cff6a/hybrid-rag/hybrid-rag/src/main/java/com/example/essentialrag/HydeQueryTransformer.java) tạo một đoạn trả lời giả định rồi thay query text bằng đoạn đó. Có thể thử như một biến thể evaluation nếu semantic recall còn kém; hiện chưa chọn cho runtime MEM-46. Nó thêm model call, có thể lệch ý câu hỏi và không được trở thành evidence/citation. Không dùng HyDE làm lý do bỏ original query hoặc bật LLM cho Search mặc định.

**ReAct và tools:** [`chatclient-and-react`](https://github.com/habuma/spring-ai-recipes/blob/f89baf57e83e2007fb0ccb96852252c1fa1cff6a/chatclient-and-react/src/main/java/com/example/reactagentfun/ReactAgentFunApplication.java) gọi ChatClient từ `ApplicationRunner` với Disney tools. “react” ở đây là agent reasoning/tool use, không phải React frontend. Các file Java đã kiểm tra không cung cấp browser/SSE production flow. MemoryOS vẫn phải triển khai và kiểm chứng streaming, cancellation, reconnect/reload và durable generation như [contract Chat](search-and-production-chat.md).

**Embabel:** [programmatic invocation](https://github.com/habuma/spring-ai-recipes/blob/f89baf57e83e2007fb0ccb96852252c1fa1cff6a/embabel-invoke-programmatically/src/main/java/com/example/embabelagent/EmbabelAgentApplication.java) minh họa gọi agent để tạo `SupportResponse`; [SupportAgent](https://github.com/habuma/spring-ai-recipes/blob/f89baf57e83e2007fb0ccb96852252c1fa1cff6a/embabel-invoke-programmatically/src/main/java/com/example/embabelagent/SupportAgent.java) khai báo action chuyển input thành trạng thái phân loại ticket. Đáng tham khảo khi có use case chọn nhiều action theo mục tiêu. Luồng MEM-46 hiện đã có thứ tự và boundary rõ, nên tiếp tục application services + Spring AI; không thêm agent platform chỉ để chạy các bước retrieval đã biết.

## 3. Những giới hạn cần giữ khi áp dụng

- Recipe dùng startup ingestion `ApplicationRunner`, Tika và `TokenTextSplitter` cho dữ liệu ví dụ. MemoryOS đã có canonical JSON/worker/claim/cleanup: đọc artifact hiện tại và structured chunker, không nạp lại file khi app khởi động.
- Một số recipe log snippet hoặc dùng `SimpleLoggerAdvisor`. MemoryOS giữ content capture tắt; telemetry chỉ ghi outcome/latency và safe IDs theo policy.
- Test đã đọc ở hybrid là `contextLoads()` bị `@Disabled`; JDBC memory và structured validation cũng là context-load tests. Chúng không chứng minh retrieval quality, permission races, bulk recovery hoặc production chat. Không dùng kết quả tutorial thay acceptance của MEM-46.
- Repo có nhiều cấu hình dependency: hybrid hiện dùng AI 2.0.1/Boot 4.1.0, một số ví dụ dùng AI 2.0.0. MemoryOS giữ một BOM 2.0.1 và baseline Boot 4.1.1, resolve/test chính stack của mình; không nhập toàn bộ build của recipe.

Tài liệu Spring AI hiện hành cũng mô tả validation advisor như schema checking + retry. Application vẫn chịu trách nhiệm domain validation, authorization và retry budget: [StructuredOutputValidationAdvisor](https://docs.spring.io/spring-ai/reference/api/advisors-recursive.html), [modular RAG](https://docs.spring.io/spring-ai/reference/api/retrieval-augmented-generation.html), [Chat memory](https://docs.spring.io/spring-ai/reference/api/chat-memory.html).

## 4. Đưa vào kế hoạch như thế nào

1. Chốt model contracts: kiểm structured-output support và cấu hình client riêng cho từng role, cùng budget/telemetry policy.
2. Search đầu tiên: metadata/provenance đầy đủ; một OpenSearch backend; đo lexical/vector fusion và deterministic dedup bằng corpus thật.
3. Chat tiếp theo: permitted-history query rewrite + original query, weighted RRF giữa query lists, typed selection/expansion có allowlist validation.
4. Production Chat: PostgreSQL conversation/generation lifecycle thuộc capability `chat`; chỉ đưa context đã authorize vào model. Test durable history và stream bằng API/browser thực.

Đây là cách dùng recipe để hoàn thiện các bước đã nhận, không thay phạm vi Search-first/production Chat hoặc quyết định vector chỉ lưu trong OpenSearch.
