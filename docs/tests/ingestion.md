# Ingestion verification matrix

This matrix identifies implemented coverage, not a claim that every service-backed scenario ran. Current-schema core/API fixtures use PostgreSQL; historical migration tests are separate. Synchronization tests use controlled provider/storage collaborators, and provider acquisition uses a local HTTP fixture. The [historical pre-cutover Google run](../increments/active/google-drive-structured-ingestion/plan.md#live-google-acceptance-after-fresh-authorization) verified native snapshots/artifacts and restart recovery. The later owner-app/explicit-link cutover was separately exercised against three real Sheets; see the [current verification ledger](../increments/active/google-drive-structured-ingestion/plan.md#owner-app-and-interface-verification). Neither run proves every format or provider failure path. JetBrains inspection was unavailable; no IDE-clean claim is made.

`WorkerFileProcessingIntegrationTest` exercises real PostgreSQL, Redis and MinIO, including extraction-artifact bytes, redelivery and cleanup. With `DOCLING_TEST_ENDPOINT`, it indexes DOCX through the real service; otherwise it uses the TXT compatibility case. `DoclingServeIntegrationTest` also requires that endpoint and verifies Vietnamese DOCX table values. Record optional-service runs explicitly: a skipped service test is not runtime evidence.
