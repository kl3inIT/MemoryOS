# Tenant lifecycle verification matrix

| Requirement | Durable verification |
| --- | --- |
| First startup creates the exact Tenant/Actor/membership aggregate, `STANDARD` account classification, Admin/Basic Groups, owner system memberships and the Admin `IAM_ADMIN` grant; identical startup replays it idempotently | `core/src/test/java/io/memoryos/iam/application/DefaultInitialTenantBootstrapperTest.java` — `createsTheExactInitialIamAggregateAndReplaysTheSameConfiguration` |
| Concurrent startup publishes one aggregate through the bootstrap-state lock | `DefaultInitialTenantBootstrapperTest.serializesConcurrentStartupAndCreatesOneAggregate` |
| Bootstrap configuration drift fails without changing the published aggregate | `DefaultInitialTenantBootstrapperTest.rejectsConfigurationDriftWithoutChangingTheExistingAggregate` |
| Failure during system-Group provisioning rolls back mixed JPA Actor, binding, Tenant, membership and Group writes | `DefaultInitialTenantBootstrapperTest.rollsBackMixedJpaWritesWhenGroupProvisioningFails` |
| Active Tenant membership resolution presents both owner and member roles and excludes inactive membership or Tenant state | `core/src/test/java/io/memoryos/iam/persistence/JpaTenantAccessResolverTest.java` — `resolvesActiveOwnerAndMemberMemberships` and `excludesInactiveMembershipAndInactiveTenant` |
| Fixed HTTP resolution ignores `X-TenantId` selection and retains the deployment Tenant | `api/src/test/java/io/memoryos/api/security/BearerAuthenticationIntegrationTest.java` — `ignoresTenantHeadersAndUsesTheFixedDeploymentTenant` |
| A bound Actor without active membership has no Tenant/capabilities, while the configured owner's protected Admin membership supplies expanded current authority | `BearerAuthenticationIntegrationTest.returnsEmptyTenantAuthorityForBoundActorWithoutMembership`, `returnsDurableTenantAuthorityForBoundOwner`, and `core/src/test/java/io/memoryos/iam/application/PostgresIamAuthorizationTest.java` — `unionsFreshGrantsAndExpandsImplicationsCentrally` |
| Global and scoped authority are distinct, and inactive membership removes both immediately | `PostgresIamAuthorizationTest.derivesScopedAuthorityOnlyFromActiveOrdinaryGroupManagement` |
| Exclusive authority writes advance `authorization_version` only on commit; shared protected writes serialize with revocation and the next request fails closed | `PostgresIamAuthorizationTest.advancesAuthorizationVersionOnlyWhenTheExclusiveMutationCommits` and `sharedResourceWriteSerializesAConcurrentRevokeAndNextRequestFailsClosed` |
| Member activation/deactivation requires fresh global `USERS_MANAGE`, is idempotent and preserves the membership row plus Group edges | `core/src/test/java/io/memoryos/iam/application/DefaultTenantMemberManagementTest.java` — `requiresCurrentUsersManageCapability` and `transitionsExistingMemberIdempotentlyWithoutReplacingMembershipOrGroups` |
| The configured `OWNER` cannot be activated or deactivated, even by a same-state command | `DefaultTenantMemberManagementTest.protectsConfiguredOwnerEvenWhenRequestedStatusAlreadyMatches` |
| The configured owner and final active `STANDARD` Admin survive deactivation/removal attempts | `core/src/test/java/io/memoryos/iam/application/PostgresGroupAdministrationGuardTest.java` — `configuredOwnerAndFinalActiveStandardAdministratorSurvive` |
| Deactivation denies the next Users request for browser and bearer callers, current identity loses its Tenant projection, inactive history remains visible, inactive login is rejected, and reactivation restores the same Actor membership | `api/src/test/java/io/memoryos/api/security/SessionSecurityIntegrationTest.java` — `userDirectoryConvergesAfterAdmissionAndLiveMembershipRevocation` |
| System-Group provisioning is idempotent, gives Basic to existing inactive members without changing activation, and gives them neither Admin nor manager state | `core/src/test/java/io/memoryos/iam/application/PostgresGroupProvisionerTest.java` — `provisionsSystemGroupsAndBasicMembershipIdempotentlyWithoutChangingTenantMembership` |
| V6 preserves Organization-era rows and renames ownership to Tenant | `core/src/test/java/io/memoryos/iam/persistence/TenantSchemaMigrationTest.java` — `v6PreservesRowsAndRenamesEveryActiveOwnershipColumn` |
| V14 adds `STANDARD`, the non-negative authorization revision and the `OWNER`/`MEMBER` role constraint, and deliberately invalidates serialized sessions; historical `ADMIN` rows fail migration actionably | `core/src/test/java/io/memoryos/iam/persistence/IamSchemaMigrationTest.java` — `v14ClassifiesActorsAddsAuthorizationRevisionAndInvalidatesSerializedSessions` and `v14FailsActionablyRatherThanReclassifyingHistoricalAdminMemberships` |
| V15 seeds Admin/Basic and preserves existing membership activation | `core/src/test/java/io/memoryos/iam/persistence/GroupMigrationSeedTest.java` — `seedsAdminOwnerAndEveryExistingMembershipIntoBasicWithoutChangingActivation` |
| OpenAPI exposes the current Tenant/IAM identity projection and lifecycle paths without legacy module routes | `api/src/test/java/io/memoryos/api/OpenApiContractTest.java` — `committedContractDescribesOnlyTheLiveBrowserApi` and generated-client drift checks |

The lifecycle suites use the unified `io.memoryos.iam` paths and the JPA transaction manager against PostgreSQL. Concrete SQL remains intentional for projections and lock/concurrency tests. API integration tests start the real HTTP composition and cover fixed-Tenant filtering, authentication, capability authorization and Actor-only session behavior. This matrix follows accepted [ADR 0007](../decisions/0007-unified-jpa-iam-and-group-authorization.md); capability-specific Source verification remains in the Connector matrix.
