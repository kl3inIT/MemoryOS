# Document capability contract

Document owns the current metadata and extracted-file reference independently of provider implementation. A Document is Tenant-scoped and either ELIGIBLE or INELIGIBLE. Its stable ID, title, detected media type, source-content SHA-256, metadata and extraction artifact reference are updated in place. PostgreSQL does not store extracted text, immutable DocumentVersion history, a current-version pointer or a processing-profile ledger.

`DocumentCommandPort.publish` creates a Document or replaces the current metadata/reference on the mapped Document under a row lock. Connector owns provenance mappings; Document never imports Connector or Ingestion types. The ingestion transaction commits this replacement and artifact adoption together with provenance and token-fenced operation completion. A failed or stale replacement rolls back and leaves the previous reference intact.

Structured extraction stores one private, SHA-256-verified JSON object under `extracted/<tenant>/<artifact>/document.json`. All routes use `memoryos-extraction-v1`, not a Google-specific Document schema or history fork. Ordered blocks carry kind, text and route-appropriate structure: Docling heading levels, table cell offsets/header flags and page/bounding-box provenance; native Sheets/XLSX/CSV coordinates, values and inert formula/merge metadata; native Docs tab/section/source indices, headings, lists and nested tables. Google input provenance is carried by the source descriptor. Docling embeds image data; native Docs preserve provider object metadata without promising downloaded image bytes. Plain text is a transient parser result used to build the artifact, not another database copy. Parser configuration is diagnostic metadata, never a uniqueness key or retry constraint. Routing and hard input/output bounds belong to the [Ingestion contract](ingestion.md).

Artifact rows are staged before object writes, marked write-complete after PUT/checksum inspection, and adopted in the transaction that replaces the Document reference. Cleanup never selects an artifact referenced by a current Document. After replacement commits, the old artifact is reclaimed by the recurring sweep. Expired uncertain writes retain a deletion tombstone and are swept daily to catch a late PUT. Retry can produce different output; only the current operation claim may publish.

Google publication is fenced by current source scope, usable credential authority revision, current item/input version and eligible non-excluded membership as well as the processing token/lease. Connector validates these inside the publication transaction; it does not rely on a previously opened Google session. Temporary folder-reconciliation ineligibility defers otherwise-current indexing rather than losing it; changed scope, disconnected credentials or removed items cannot publish stale artifacts. The existing current Document/reference can remain stored after invalidation, but that is not permission to read it. Google sources are RESTRICTED and excluded from the FILE PUBLIC access resolver; Document ELIGIBLE status is not an ACL grant. Authorization and access exclusions are defined in the [Connector contract](connector.md).

When Connector removes provenance, `DocumentCommandPort.removeUnreferenced` deletes the Document only after no live mapping remains; artifact cleanup follows. FILE REMOVE_ITEM/DELETE_SOURCE semantics remain provider-object deletion followed by relational/provenance cleanup, including after Tenant deactivation. V12 copies current metadata/reference then drops version history, stored text and profile attempts. Per the dev/staging scope, missing legacy artifacts do not block migration; use normal FILE reindex afterward. V13–V15 add server-owned input writes, Google credential authority and durable source synchronization without changing this current-Document model. Raw input objects and connector input snapshots remain separate from extraction artifacts. No retrieval endpoint, embeddings, chunks, search-index success markers, ACL/Groups enforcement, reader linking or document viewer are introduced.
