# Document capability contract

Document owns the current metadata, extracted-file reference and current chunk set independently of provider implementation. A Document is Tenant-scoped and either ELIGIBLE or INELIGIBLE. Its stable ID, title, detected media type, source-content SHA-256, metadata and extraction artifact reference are updated in place. PostgreSQL stores bounded current chunk text/provenance, not a duplicate full extracted-text column, immutable DocumentVersion history or embedding arrays.

`DocumentCommandPort.publish` creates a Document or replaces the current metadata/reference on the mapped Document under a row lock. Connector owns provenance mappings; Document never imports Connector or Ingestion types. The ingestion transaction commits this replacement together with token-fenced operation completion. A failed or stale replacement rolls back and leaves the previous reference intact.

Structured extraction stores one private, SHA-256-verified JSON object under `extracted/<tenant>/<artifact>/document.json`. The artifact schema `memoryos-extraction-v1` orders blocks with kind, text, optional heading level, table cell offsets/header flags, and source-provided page/bounding-box provenance. Image data is embedded in this self-contained artifact. Plain text is a transient parser result used to build the artifact, not another database copy. Parser configuration is diagnostic metadata, never a uniqueness key or retry constraint.

Artifact rows are staged before object writes, marked write-complete after PUT/checksum inspection, and adopted in the transaction that replaces the Document reference. Cleanup never selects an artifact referenced by a current Document. After replacement commits, the old artifact is reclaimed by the recurring sweep. Expired uncertain writes retain a deletion tombstone and are swept daily to catch a late PUT. Retry can produce different output; only the current operation claim may publish.

When Connector removes provenance, `DocumentCommandPort.removeUnreferenced` deletes the Document only after no live mapping remains; current chunks cascade and artifact cleanup follows. Synchronous `DocumentChanged` events let Ingestion retain projection deletion work beyond that deletion. V12 removed history/full stored text; V17 adds only current chunks, artifact reader protection and current Search readiness. Missing legacy artifacts require the existing Source reindex flow.

Every successful publication assigns a new `content_generation` and clears current chunk/readiness/error markers. `DocumentChunkPort` supplies bounded checksum-verified artifact reads, current chunk publication, batch current-generation checks, current passage reads and readiness transitions. The chunk convention prevents reuse of an obsolete chunking representation. An expiring reader row protects an old artifact until its bytes have been read. Late chunk publication requires the matching current generation under a Document lock. The [Search contract](search.md) owns chunking/indexing and retrieval behavior; Document never imports Retrieval or Ingestion internals.
