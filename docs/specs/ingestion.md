# Ingestion capability contract

Ingestion owns asynchronous indexing and cleanup orchestration. It depends only on public Connector, Document, Object Storage, and Tenant APIs. Provider parsing enters through `SourceContentExtractor`; no Tika or AWS SDK type crosses the core boundary.

PostgreSQL operation rows are the sole durable authority for Tenant ownership, eligibility, stable delivery identity, dispatch evidence, processing tokens, leases, retry counts, and terminal state. db-scheduler relays bounded eligible index and cleanup identifiers to separate versioned Redis Streams. A consumer reloads one operation, acquires a fresh identifier-scoped claim token and two-minute lease, and renews long-running indexing through token-fenced updates. Every repository predicate retains the durable `TenantId` without ambient context. Index work carries an immutable `StoredObjectReference`; the worker opens and verifies provider metadata, then streams `ObjectContent` into extraction outside database transactions. Final publication runs in one transaction and requires the current token, active Tenant, non-deleting Pair/item, and current item version. Stale or obsolete completion rolls back both Document and provenance changes.

Redis messages contain only `tenant_id`, `operation_kind`, `operation_id`, and `delivery_id`. Manual acknowledgement occurs only after durable completion or authoritative proof that the delivery is missing, terminal, superseded, duplicate, or protected by another live lease. Pending reclaim requires both Redis idle evidence and an expired or absent PostgreSQL processing lease. Bounded rediscovery republishes nonterminal work after Redis restart, trim, or loss; publish/evidence races may duplicate but cannot lose the PostgreSQL operation. Inactive-Tenant indexing is cancelled before dispatch, while cleanup remains eligible after deactivation. The runtime has no direct PostgreSQL polling executor or alternate compatibility path.

The FILE adapter uses Apache Tika 4.0.0 minimal PDF, Microsoft, text, and core modules. It detects actual content, supports PDF/DOCX/UTF-8 TXT/Markdown, disables OCR and embedded recursion, limits output to 2,000,000 characters, and returns typed unsupported/encrypted/malformed/timeout/write-limit/internal failures. Each extraction runs in a bounded child JVM; timeout or shutdown forcibly terminates that process so malformed parser work cannot survive a terminal result.

Cleanup is allowed after Tenant deactivation but cannot create content or access. For REMOVE_ITEM and DELETE_SOURCE, Ingestion asks Connector for adopted objects, idempotently marks each `DELETE_PENDING`, performs provider deletion, and only then asks Connector to remove provenance, attempts, upload associations, versions/items/Pair/Connector, stored-object metadata, and unreferenced Documents. Generic abandoned-upload cleanup is a separate object-storage task and never selects adopted objects.
