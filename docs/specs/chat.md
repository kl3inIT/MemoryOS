# Chat session contract

## MEM-81 in-flight file backend

The local attachment change adds owner-private UserFiles independently of conversations. `/api/chat/files` provides policy, idempotent upload initiation (`requestId` plus filename/type/size/SHA-256), finalize, recent-list/status, processing retry and deletion. API selects the `CHAT_FILE` storage purpose; browser input cannot select it. Finalize verifies storage outside the ownership transaction, then rechecks active membership/owner and atomically adopts the upload and queues PostgreSQL work. Replaying a completed finalize does not enqueue again. List/get do not return raw keys or plaintext. Stable extraction failure codes accompany failed metadata.

The browser repeats initiate/finalize once on a fetch network TypeError with the same request/file identity, without repeating PUT. It does not retry HTTP authorization/validation failures or canceled requests. Existing recent-file/finalize/expiry paths remain the recovery surface after reload; this is not resumable chunked upload or persistent browser drafts.

Worker publication saves the normalized plaintext and a private Document reference together, fencing stale work with a claim token/lease. `READY` here means content publication, not search readiness. Delete makes the file unavailable first; separate durable cleanup removes raw bytes and the Document projection/artifact. A historical upload receipt survives cleanup. Source Document cleanup respects live UserFile references.

Messages carry ordered descriptors in one `files JSONB` column; command replay compares the ordered file IDs. The frontend sends server file identities, not binary data, through the native assistant-ui attachment adapter. The composer has one action row: paperclip, model selection and Send/Stop. The paperclip opens a Radix popover with upload and three recent files; the full picker/recovery actions open in a separate dialog. Message editing reuses this compact picker. Project files live in the workspace Files section, separate from the name/instructions editor; removing a Project association does not delete the file. Custom Personas reuse the picker, and their file list overrides the Project list, including when empty. The picker preserves unavailable selected identities until the owner explicitly removes them, and file deletion uses the existing confirmation dialog.

The native composer is wrapped only for the application readiness rule: Gửi and Enter are blocked while any attachment is running/incomplete, lacks a server file identity, or the draft exceeds 20 files. Text remains editable. Adapter `send` also validates the ready identity; this does not replace backend admission checks. The library's default send gating alone does not enforce worker readiness.

Owner-private `GET /api/chat/files/{fileId}/text` reads at most 16,000 Unicode code points from cached extraction; zero-based `offset` and returned `nextOffset` use PostgreSQL character semantics, not UTF-16 offsets. `GET /api/chat/files/{fileId}/content` streams the original adopted object with attachment disposition, `application/octet-stream`, `nosniff` and `Cache-Control: no-store`. Both require current owner/Tenant authority and READY content; raw download rechecks ownership, membership and object metadata after opening storage and closes rejected streams. Raw keys and signed download URLs are not persisted in message descriptors.

The history reader renders text as inert text, follows the returned cursor and offers an authenticated original download. PNG/JPEG/WebP preview fetches owner-authorized bytes on opening, uses the existing assistant-ui object-URL lifecycle hook, and releases the URL on closing. Reader queries have no inactive cache retention. Shared transcripts render descriptors without private reader/download actions. This UI does not grant file authority through transcript sharing. The AI SDK converter places sent user files in `message.attachments`; `MessagePrimitive.Attachments` renders them and editing retains file/image identities from that collection, not only message parts.

Vision turns load owner-authorized original bytes inside the cancellable file-work scope and pass native ImagePart messages to the SDK. The local OpenAI HTTP test verifies the exact data URL, not only an intermediate Prompt. Non-vision turns preserve text markers for history/workspace images without reading bytes or charging image tokens, matching Onyx model switching. Image admission uses a 4096-token heuristic per image; this is not exact provider tokenization or a billed usage value. Native response usage remains authoritative. No Azure-specific cap is invented for the current OpenAI adapter.

File context/tools share a bounded citation namespace with Source search. API history preserves nullable `fileId` versus Source `documentId`/`generation`. Optional `fileLocation` records either a Unicode character `offset`/`count` from `read_file`, or an indexed `generation`/`ordinal` from `search_files`. Character citations open and highlight that cached-text window. Indexed citations reuse the Search document reader through owner-private `GET /api/chat/files/{fileId}/passages?generation=…&from=…`; the server resolves the private Document, rechecks current generation and owner/Tenant authority after IO, and returns at most 20 passages. Distinct locations receive distinct citation IDs. Whole-file context and historical citations without a location remain explicitly whole-file; there is no invented PDF page or exact-passage guarantee for those citations. When private search dependencies fail, `search_files` advises `read_file` for cached text; authorization and cancellation exceptions are not swallowed. Control-plane expiry turns abandoned uploads into `FAILED/UPLOAD_EXPIRED`; they require a new upload. Expired worker claims can be reclaimed while late publishers remain fenced.

This remains unshipped and is not completed MEM-81. Two real-model vision cases and isolated large-XLSX parser resource measurements passed on 2026-09-12; exact boundaries are in the [active increment](../increments/active/chat-attachments-production/verification.md#live-vision-và-đo-tài-nguyên--2026-09-12). Those checks do not certify integrated upload/worker/model/browser release acceptance or full worker/API resource sizing. OCR is explicitly deferred by the user; the private deployment manifest still limits files to 100 MiB, and local XLSX 100/250 MiB tests do not prove OCR 250 MiB acceptance. The existing Source-backed Chat contracts below remain unchanged.

## Browser integration

`/` starts a new conversation; `/chat/{sessionId}` loads a private selected-branch transcript. The shared application sidebar contains New chat, Search, expandable project folders and paginated conversation history. A saved conversation has one header with its title, Share and an overflow menu; Chat/Search mode switching remains on the empty Chat and Search pages. Sidebar navigation does not cancel a running inference. The mobile sidebar is the existing modal drawer. Welcome and composer are centered together before the first message; the conversation composer stays at the bottom. Layout and interaction follow the accepted Onyx reference while preserving MemoryOS tokens and Radix controls. ModelSelector, MarkdownText, Logos, InlineCitation, Sources, ThinkingIndicator, EditMessage, MessageActions, MessageBranches, FeedbackDialog and ThreadList are CLI-installed assistant-ui elements under `web/src/components/assistant-ui/elements`. The controlled editing/branch/feedback elements call MemoryOS commands; `ThreadListItemMorePrimitive` supplies the conversation menus. MarkdownText accepts the citation plugin and app Copy control. InlineCitation exposes the registry specimen as a streamed marker using the existing Radix HoverCard. Sources retains the compact toolbar trigger and opens the application-owned source panel. The picker displays one model-name row without repeating the raw model ID; the composer omits a permanent keyboard-helper note. Native Logos cover OpenAI, Claude and Gemini; unrecognized model names use the generic icon without changing catalog IDs or provider routing. Custom assistant redesign, attachments and voice controls remain outside this UI change.

The composer model picker loads the session-aware authorized catalog, groups models by provider, and sends `modelConfigurationId` per turn. Automatic leaves the ID absent so the backend applies Persona → Tenant default resolution. A selected ID is a browser-session preference scoped to Actor; the backend revalidates every send. Selection is captured before asynchronous admission and disabled while running/recovering. A backend fallback updates the displayed selection and shows a notice. Thinking effort remains provider/admin configuration, not an unsupported browser override. Catalog administration is separate MEM-77 work.

`useChatRuntime` from `@assistant-ui/ai-sdk` connects native assistant-ui primitives to Vercel AI SDK message state. `MemoryOsChatTransport` implements public `ChatTransport` and uses the generated Java API client and SSE parser. It converts named events into UI message chunks; it does not execute tools or create another message store. Stable UUID request IDs and server-assigned user/assistant IDs are retained. A new session is created lazily from the first question, including the draft's project ID when present. After acceptance, the URL changes to its session while the same runtime, composer and SSE reader remain mounted; no history hydration or extra metadata read occurs during promotion. Opening a different conversation or project resets the draft. Metadata invalidation after rename/move updates the header without reinitializing the transcript.

The composer supports native Enter/Shift+Enter and IME handling, with a 32000-character limit. Markdown/code blocks and copy use native message parts; links use explicit HTTP(S) URLs and open outside the app. Native viewport behavior follows output while at the bottom, preserves an upward-scrolling reader, and offers a return-to-latest control. Stop calls the Java cancel endpoint while retaining the reader; only committed cancellation invokes native runtime cancel. History metadata renders saved FAILED/CANCELED outcomes after reload.

The adapter ignores duplicate sequences, checks run IDs/cursors, and makes at most three stream connection attempts with a 65-second per-connection limit. It resumes from the last applied cursor. Reset/gap or exhausted reconnect falls back to saved history, polling only the reply after its stable USER parent every two seconds for at most 31 minutes, covering the server's maximum 30-minute deadline and finalization grace. It never resubmits the question automatically. EOF is not a successful terminal outcome. If status cannot be confirmed, sending remains disabled and Check conversation reloads authoritative history. Stop during send admission is retained until the reservation supplies an assistant ID. HTTP 401/403/404 hides the current transcript and refreshes identity. Route unmount and authority changes release subscriptions; they do not cancel backend execution.

Browser bounds: stream response 8 MiB per connection, reply 1000000 characters, complete history 8000000 characters/100 pages and a 30-second history fetch deadline. Exceeding history bounds reports an unavailable conversation instead of silently dropping its prefix. These are browser protection limits, not configurable backend context limits or a claim of unlimited history support. The transport retains only the current text prefix needed to reconcile a durable fallback with SDK-owned text.

## Conversation editing, assistants, projects and collaboration

V36 extends the existing tree without changing old message IDs. `chat_command` records SEND, EDIT and REGENERATE receipts per session/request UUID, including the target, text and requested model. A replay returns the same reservation; changing these inputs under one UUID conflicts. EDIT creates a sibling USER plus ASSISTANT; REGENERATE creates only an ASSISTANT under the selected USER. Both run through the same native execution, budget, Stop and finalization path. Selecting a stored version changes its parent's latest child, preserves descendant branches and generates nothing. The caller supplies the expected selected child to detect competing selections. Settings, branch mutations and admission recheck current owner/Tenant authority, serialize through capability repository locks, and reject changes to the conversation's context while a reply is active.

Rename changes the header/sidebar title. New browser conversations start with a whitespace-normalized first-question fallback, limited to 40 whole grapheme clusters (preserving joined emoji and combining marks) and the API's 200 UTF-16-unit limit including the truncation marker. After a completed answer, the browser requests `POST /api/chat/sessions/{id}/title`; the server atomically claims naming once, resolves the authorized model through the existing catalog/native inference lifecycle, and generates a bounded title (10-second deadline, 128 output tokens, at most 80 Unicode characters stored). This separate best-effort request never blocks answer streaming. Failure retains the fallback; manual rename or a changed session snapshot wins over late generation. V40 preserves existing session names and does not mass-rename history. The header truncates visually while retaining the full title as a tooltip. No naming queue/worker is added.

Delete hides the session from every private/shared read and list, cancels any active reply and discards local replay/readers for all branches. Conditional terminal writes cannot resurrect the deleted session. This is a soft deletion; no restore or hard-purge promise accompanies it. Deleting a Project instead unlinks its sessions and retains their history. Deleting a custom Persona retains its reference for history but blocks subsequent admission until an available assistant is selected.

`/assistants` provides owner-private Persona CRUD and the shared builtin assistant; builtin changes require `MODELS_MANAGE`. Fields are name (200 characters), description (2000), instructions (32000), up to eight starters of 1000 characters, at most 100 distinct source IDs, Search enabled, an authorized default model, and optional context/output caps. Model capabilities and provider options remain catalog-owned. A source selection narrows the actor's current authorized search scope on every tool call; empty selections mean all authorized sources. Retaining an unavailable source ID preserves the restriction, rather than widening to all sources when the last selected source disappears. New unauthorized source IDs are rejected. Pickers page through eligible sources and settings rather than truncating to the first page. The actual current source policy remains PUBLIC FILE.

Builtin Persona provisioning inserts only when absent; create/send/catalog reads no longer overwrite saved instructions or model selection. `JpaPersonaRepository`, `JpaProjectRepository`, `JpaChatSharingRepository` and `JpaChatFeedbackRepository` own lifecycle operations and scoped reads. Services own authorization and transaction boundaries; `@Version` detects stale editors. The catalog uses the same Spring Data approach for providers/models/defaults; tree/command/conditional execution operations remain in `JdbcChatRepository`. No IAM repository is migrated here; that handoff is recorded in MEM-55/MEM-36.

`/projects` lists private projects; `/projects/{id}` edits instructions and manages conversations. `ChatWorkspaceService` creates a conversation with its assistant/project atomically and applies combined settings atomically; an unavailable project rolls back an assistant change. A custom Persona supplies instructions even when empty and takes precedence over Project instructions. The builtin assistant adds Project instructions. Resolution reads the Persona model binding and configuration revision in one SQL snapshot under the owner lock and a shared Persona row lock; admission repeats the locked read and checks the revision. The row lock also excludes edits to the builtin Persona by another owner. Admission captures the effective instructions, options and configuration revision in the in-memory turn context, so later editor changes do not change an admitted run. No transcript from another project conversation is imported.

Creating a Project asks only for a name, then opens its workspace with instructions, the native Chat composer and recent conversations. Instructions and the name are edited from that workspace. No empty session is created merely by opening a project or typing. Conversation menus move/unlink the existing session; desktop drag and drop uses the same command. Project deletion preserves conversations in general history.

Conversation rows rename inline: Enter saves, Escape cancels, and a failed save retains the draft. Header and row menus provide sharing, project membership and confirmed deletion; existing assistant settings remain in the header menu. Message editing is inline and keeps its draft and request UUID after a failed command. Regeneration and saved-version controls call generated server commands, then reload the selected branch and resume any admitted reply. Previous versions remain selectable. Feedback has separate positive/negative buttons and a reason/comment dialog; clicking the saved reaction again removes it. Each answer version retains its own feedback. The server tree remains authoritative after reload. Starter buttons fill the composer. Busy or uncertain execution blocks additional edits and sends until status is confirmed; canceling the inline editor remains possible after a failed command.

The sharing dialog creates/copies the link without closing, exposes a selectable URL when clipboard access fails, and lets the owner revoke in the same dialog. Reopening fetches the current sharing revision and prevents writes until that fetch succeeds. Access choices are native radio controls usable with the keyboard.

Sharing starts private. The owner can enable/revoke the session link with an expected revision. `/shared/{sessionId}` requires an active same-Tenant membership and reads only the currently selected saved branch through dedicated shared APIs. It has no composer, editing or Stop and does not subscribe to the owner's inference. The page rechecks access using the lightweight shared-session endpoint on focus and every 30 seconds, removing displayed content on denied reads. Full history loads on entry, focus or manual reload; the periodic access check does not paginate the transcript. Every API read revalidates sharing and membership. Sharing grants transcript access only: citation previews still use the reader's source authority. Revocation cannot retract text already viewed or copied.

Feedback belongs to the owner Actor and a specific saved ASSISTANT output with nonblank content. It supports nullable positive/negative rating, comment (4000 characters), reason (100), and removal; at least a rating or nonblank comment is required. Regenerated outputs have independent feedback. Shared readers cannot mutate feedback or conversation state.

## Owner authorization

`ChatSession` belongs to the configured Tenant and an Actor. An active membership is necessary; even a different member/admin cannot read another Actor's private session through these endpoints. Identity comes from the existing principal; Tenant/owner fields are not accepted in the creation body. Missing, wrong-owner and inaccessible session lookups return `CHAT_UNAVAILABLE` without disclosing contents. The existing API membership filter rejects revoked membership with 403 before Chat handling.

`Persona` is the AI role configuration, not a user profile. The built-in default Persona is provisioned idempotently when an authorized session is first created; subsequent creates reuse its identity and apply the configured defaults. `memoryos.chat.persona.name`, `.instructions` and `.model` have initial defaults MemoryOS, a general assistant instruction, and gpt-5-mini. The runtime registers this configured model as a native Embabel LlmService; the deployment model initializes the catalog once, and each turn explicitly selects its native service. Persona editing UI is not implemented. Backend model selection and access now follow the [catalog contract](chat-models.md).

`ChatMessage` stores a root, USER or ASSISTANT node and its parent/latest child. Root nodes are not returned as visible history. Latest child must be a direct child in the same session, enforced by a deferred composite FK. One root and at most one RUNNING assistant per session are enforced by partial unique indexes. `runId` is the reserved assistant message ID; no separate ChatRun table exists.

OpenAPI and browser clients are generated from controllers, with explicit required/nullable response fields.

## Internal persistence contracts

Within a transaction, IAM shared-lock revalidation precedes the session write lock. A send reservation atomically creates USER and ASSISTANT nodes and updates latest-child pointers. Retrying the same client request ID with the same parent/text/requested model ID returns the original message IDs and selection; changing any of these fields conflicts. A different send while a reply is RUNNING conflicts. Send accepts an optional stable `modelConfigurationId`; the [catalog contract](chat-models.md) owns precedence, access and fallback.

The USER row retains `original_assistant_message_id`, written with the initial pair. Retry resolves that original assistant even if latest-child selection has changed or another turn is RUNNING; it neither changes branch selection nor creates messages. The original reference is required on USER rows and must identify a direct child in the same session. It is internal persistence data, not a history response field. Branch changes are exercised with database fixtures; edit/regenerate endpoints remain unimplemented.

Request idempotency, composite tree constraints and conditional PostgreSQL terminal writes are MemoryOS implementation choices, not claims of identical Onyx mechanisms. Their rationale, source evidence and costs are in the [Phase 2.1 comparison](../increments/active/mem-11-production-chat/design.md#phân-biệt-onyx-và-lựa-chọn-phase-21). Private-only access is this phase's implemented scope; planned sharing and any future administrative transcript access require their own authorized operations.

Continuation accepts the selected leaf, not arbitrary branch edits. Session history is bounded to 9999 nodes including the root; input text is limited to 32000 Java characters. Internal reservations receive a positive timeout up to 30 minutes. A terminal write accepts up to 1000000 characters, changes RUNNING once, and cannot overwrite a terminal result. Local Stop accepted before the immutable terminal decision wins cancellation. PostgreSQL converts writes after the durable deadline to FAILED. Finalization reads back the actual DB winner before publishing an outcome; a successful conditional write does not mean generation succeeded.

Flyway V18 owns the session schema; V19 adds execution metadata, and V20 removes the former DB Stop marker without rewriting V19. V21 adds the provider/model catalog and historical request/selection IDs. SQL and locks stay in `chat.persistence`; actor-facing application services own access and transactions. No temporary execution profile, fixtures, provider credentials or QA files are installed in the application.

## Execution lifecycle

The API owns a Spring SimpleAsyncTaskExecutor using virtual threads, without replacing Boot's applicationTaskExecutor. ChatTurnService admits at most the configured number of active turns, including outcomes waiting for a DB retry or native work to stop; there is no Chat queue or worker. Native Reactor cancellation terminates the stream on Stop. Shutdown signals cancellation and waits up to five seconds for task finalization before Spring closes the executor. Spring owns executors; Search tracks actual tool/native bodies so cancellation can interrupt them and retire resources after they exit. A process kill or exhausted drain can still lose unsaved partial output.

ChatTurnPersistence loads authorized product context. The builtin Persona is configuration-backed and refreshed on a new send, including existing sessions; the Phase 5 editor must explicitly transfer settings ownership. The current question plus instructions is validated before inserting messages. ChatTurnSetup resolves native Embabel messages and bounds context with the selected adapter's Spring AI tokenizer plus framing allowance (O200K for the current OpenAI adapter). The DB read is capped at 201 ancestor nodes and 1 MiB of content; model input omits root/placeholder nodes and an orphan oldest assistant. Selected context is in RAM; no full configuration snapshot is persisted.

ChatModelExecutor calls native PromptRunner, streamer and tool loop. StreamingLlmService binds verified streaming capability without a discovery inference. ChatModelGuard validates finish metadata, applies the final-cycle request policy, and records native LlmInvocation usage once per inference. Native Embabel computes totals/cost and evaluates configured budgets. Missing usage/pricing stays unknown; there is no custom pricing engine. Search tool accounting and authorization boundaries are specified under Grounded Chat below.

Stop authorizes the assistant/session and signals local execution directly. A bounded array of session command locks prevents Stop from overtaking reservation/registration. No active-row Stop polling or replica signaling remains. PostgreSQL sets the authoritative deadline; JVM clocks must remain synchronized for local cancellation timing. Reconciliation closes up to 100 expired RUNNING rows per pass after a five-second finalization grace. No model/tool call is retried. Terminal persistence can retry while keeping the active slot; process death can lose output not yet saved.

The provider composition owns reusable synchronous/asynchronous Spring AI SDK clients, explicit timeout, disabled automatic retries, close hooks and native observations/meters. `ChatModelBinding` retains the native SpringAiLlmService and provider final-request policy; each run resolves it into its RAM setup before dispatch. Decorating a model preserves converter/pricing/capabilities/adapters. The generic executor uses `Ai.withLlmService` and has no OpenAI options cast. The [backend catalog](chat-models.md) owns selection, Group/Persona access, organization BYOK and bounded client leases. OpenAI is the shipped adapter; model selector/admin UI and the real local adapter are separate follow-up work.

Provider endpoints are server-owned configuration. HTTPS remains the default; explicitly configured HTTP endpoints are supported for internal deployments. HTTP(S), host and URL structure are validated before SDK construction; URL credentials, query strings and fragments are rejected without echoing their values. Network transport protection is a deployment responsibility; Chat does not infer trust from a hostname or categorically reject internal HTTP.

## Streaming and reconnect

`StreamBufferWriter` owns ordered text/outcome events in RAM. `text-delta` and `outcome` carry the assistant ID and sequence; only an outcome published after the terminal transaction commits confirms completion/cancellation/failure. Missing, evicted or expired prefixes produce an unnumbered `reset` with `BUFFER_MISSING`, `BUFFER_GAP` or `BUFFER_EXPIRED`. Consumers then read history and poll RUNNING with a bounded policy; they must not start a new inference automatically.

The MVC controller returns `ResponseEntity<Flux<ServerSentEvent<Object>>>`, following OrgMemory's HTTP composition style. Spring owns SSE writes and subscription lifecycle. `ChatEventStream` reads bounded batches on the existing virtual-thread executor, with prefetch 1 and resource cleanup on cancellation/error/completion. HTTP disconnection or connection timeout closes only its reader. The model writer is independent. MVC socket writes remain blocking on Boot's application executor; this is not a WebFlux migration or a claim of higher throughput.

Authorization and cursor preflight run synchronously before the response. Reader allocation is deferred until subscription, and each subscription owns its own cleanup; an unconsumed publisher holds no reader slot. Terminal persistence uses a nonblocking finalization claim independent of the state monitor, so a slow terminal write does not hold the monitor used by Stop and text callbacks. Terminal publication is serialized. Admission is released exactly once after both persistence and actual work retirement complete.

Defaults under `memoryos.chat.stream`: 4 MiB per run, 64 MiB total accounted replay budget, 10-minute TTL, 16 KiB text chunks or 25 ms flush, 128 KiB reader lag/batches, 4 readers/run and 64/process, 15-second heartbeat and 10-minute connection timeout. Accounting includes UTF-8 payload plus fixed per-event overhead; it is not a JVM heap measurement or serialized-wire byte limit. Buffer slots conservatively reserve the full per-run budget, so default retention admits 16 streams; completed streams are evicted first. Slow readers reset without blocking writers. Cursor-based replay and live reads share one sequence under the buffer lock; network and DB operations do not run under that lock.

Maintenance and flush use two Spring-managed virtual scheduler threads so a DB reconciliation wait does not block flushing. Chat executors are excluded as default candidates, preserving Boot's application executor. The existing Nginx honors `X-Accel-Buffering: no`; responses use `Cache-Control: no-store, no-transform`. The generated SSE SDK is retained, while the parser excludes this operation from TanStack query generation because its cursor represents a stream, not page fetching. Restart loses RAM replay; PostgreSQL history and deadline reconciliation remain authoritative.

Configuration: MEMORYOS_CHAT_API_KEY (fallback SPRING_AI_OPENAI_API_KEY) and optional MEMORYOS_CHAT_BASE_URL supply server-side provider access. Missing credentials reject a new send before reservation while history/cancel and other capabilities remain available. The OpenAI adapter takes an explicit options family; it does not require a GPT-5 model name. gpt-5-mini remains the live baseline, not certification of every compatible or local model. Execution defaults are concurrency 8, deadline 2 minutes, six cycles, 4096 output tokens, 32000 context tokens and 1000000 answer characters. Explicit token/cost caps use native Budget; a monetary cap requires configured input/output pricing. Basic pricing does not certify cached-token billing parity. Provider transport has automatic retries disabled.

A nonblank provider finish reason, including length, ends an answer normally when text exists; empty answers fail with CHAT_EMPTY_RESPONSE. EOF without terminal metadata fails and keeps partial text. Incomplete tool arguments at a length boundary must not execute. Safe failure codes and exception class names provide diagnostics; prompt/provider exception payloads are never logged. Send returns stable message IDs, and history carries the authoritative status used for reload.


## Grounded Chat — Phase 3.1

The backend registers `searchKnowledge` through Embabel `@LlmTool`/`Tool.fromInstance` for tool-capable bindings. Arguments contain one to three focused queries and optional explicit source/date filters. Two native helpers produce semantic and keyword expansions once per turn; later calls omit this expansion unless entering a previously unsearched source type. Tool queries and the original question remain. RRF k=50 sums semantic (1.3), keyword (1.0), tool (0.7) and original (0.5) contributions, including duplicate roles within a group: semantic/tool/original with identical text totals 2.5. Up to eight grouped queries retain separate weights; identical text shares embedding/hybrid IO. Both groups use the configured hybrid pipeline (default 50/50 lexical/vector), matching Onyx's OpenSearch adapter. The tool's `hybrid_alpha=0.2` is not an effective 80/20 mix in that adapter.

Retrieval checks current source eligibility and generation before titles/content/metadata reach any model or event. Adjacent hits merge by document/generation before candidate limits. Selection sees at most three chunks around each section's best-ranked anchor plus permitted source/date/author metadata under a total token budget. Malformed optional author JSON yields no author and does not drop otherwise eligible documents. Reading progress bounds titles to 255 Java characters without splitting a surrogate pair; final citation titles retain their existing limit. Selected sections first read two neighbors around their full boundaries; separate typed classification chooses NOT_RELEVANT, MAIN_SECTION_ONLY, INCLUDE_ADJACENT_SECTIONS or FULL_DOCUMENT. FULL_DOCUMENT reads at most five neighbors per side and never widens when no neighbor exists. Expanded overlaps merge before bounded evidence/citations. Expansion reuses the authorized search set and checks generation; independent source previews check current permission.

`ChatPrompts` and `SearchPrompts` retain the applicable Onyx prompt baseline at f9e3de3, adjusted for the registered tool and native structured output. The default Persona instructions are configurable through `memoryos.chat.persona.instructions`; the current UTC datetime placeholder resolves into the in-memory turn setup. Search guidance is included only for a tool-capable binding. Actual inference requests receive inline citation reminders once evidence exists and a final-cycle reminder when tools are disabled. These reminders do not modify the stored transcript or user message. Web search, user-directory context and other unavailable capabilities are not advertised.

`memoryos.chat.search` configures candidates (30 merged sections), sections (10 selected), selection-tokens (6000), context-tokens (8000), max-calls (3), helper-timeout (60 seconds, capped by the remaining turn deadline), auto-detect-filters (true), and cleanup-timeout (1 second, positive and at most 5 seconds). Helpers use the selected native binding/process with no tools and `withoutThinking()`; the adapter applies the supported helper reasoning effort after native conversion, independently of answer settings. See [model options](chat-models.md#credentials-and-provider-extension). Two native binding attempts remain allowed, within one helper deadline. The helper ceiling is `2 * (3 + maxCalls * (2 + sections))`: two rewrites, one time inference, and per-search source inference, selection and classification. Missing native usage leaves accounting unknown. Parallel requests reserve input/output token and known cost allowance before IO; native Embabel records usage once. Unknown/failed requests retain their allowance. The stream cycle/final-tools-off limit remains separate.

Tool-capable turns reserve up to 4096 input tokens (at most one third of the configured input limit) for tool context. The full transcript remains unchanged in PostgreSQL. The guard counts text, tool arguments/results, reminders and tool schemas before provider inference. Helpers bound history/candidate/neighbor text; truncation is marked. Selected evidence is additionally bounded before it enters the loop. Invalid rewrites retain a valid original/tool query; invalid selections fall back to ranked candidate numbers; invalid classifications retain the matching passage. Model-invented document IDs are never accepted. Empty evidence and unavailable search produce distinct tool results; cancellation and budget failures cannot trigger fallback.

Blocking tool continuations run on a bounded scheduler outside provider IO threads. Independent rewrite/filter, hybrid, and expansion/classification phases each use at most four concurrent tasks, propagate observation context, and preserve input order. Failures cancel siblings. Stop/deadline seals admission to queued/running tool and native helper work and interrupts running bodies. SearchTool waits up to cleanup-timeout for actual completion, including native usage recording. If IO ignores interruption, the terminal outcome can still be persisted; its usage/cost stays unknown. The native process, model-client lease and execution slot remain owned until that work actually exits. Late work cannot start another provider attempt or publish progress, citations, text or updated terminal accounting. This retains backpressure instead of admitting unbounded abandoned work; a permanently stuck provider consumes its slot until process restart. Helpers use a separate deadline covering native binding attempts; helper timeout falls back only while the turn remains active. The provider may charge work already accepted. Existing partial/terminal winner and RAM replay semantics remain.

V34 adds only `chat_message.sources`, a JSON array bounded to 24 entries and 128 KiB. Each entry contains a turn-local `citationId`, document/generation IDs, title, inclusive ordinal range and per-chunk provenance. Overlapping/adjacent passages are merged; repeated identical evidence reuses its citation number. The model is instructed to cite `[n]`. Source metadata identifies supplied evidence; it does not by itself prove that every sentence or model-produced citation is supported. The browser transforms prose citations and resolves them only against the current message's server-owned sources. Inline/fenced code is preserved and unknown citations remain plain text. Resolved prose citations are compact numbered title chips with an excerpt on hover or keyboard focus. The Sources action beside Copy opens an answer-specific right panel on desktop; selecting a source or clicking its inline chip opens the inclusive cited range in that panel, with Back to sources and focus restoration. Mobile uses a modal right drawer with keyboard focus containment. The open panel follows the selected message in native runtime state as sources arrive. Chat and Search share `DocumentPreviewContent` and the generated document reader; Search retains its dialog. Source list excerpts and hover previews load from that same reader when displayed, using the requested generation, with no new endpoint or persisted excerpt. Full document preview queries use zero stale time and release data after the last observer closes. Excerpts use a separate 30-second cache keyed by Actor, authorization version, document, generation and read window; repeated hovers reuse it, while opening the reader always performs its own current read. A first source-list opening can still read up to the bounded source count (24); no unmeasured performance guarantee is claimed. An unavailable source does not remove the historical answer.

Sources commit atomically with the assistant's content and terminal outcome, including partial canceled/failed answers; a losing terminal write cannot replace them. History returns `sources` for every message (empty for user messages and legacy answers). Source metadata has no live document FK and no transitive ACL check on conversation history: an update/delete does not rewrite an old answer or grant permission to open the current document.

SSE `search` events carry `{assistantMessageId, sequence, toolCallId, stage, source, search, documents}`. SEARCHING publishes at most eight actual query texts and effective source/time filters before retrieval. EXPANDING publishes at most ten authorized selected document ranges before reading neighbors. These reading candidates are separate from final citations. STARTED, SELECTING, SOURCE, COMPLETED and FAILED remain; `source` is non-null only for SOURCE and `search` only for SEARCHING. Events share the text/outcome sequence, replay byte limit and TTL. Native tool IDs correlate them. The transport retains at most 16 recent tool progress entries and deduplicates replay by sequence. The UI shows query/filter details and documents being read, then sources/citations. Buffer loss restores final sources from committed history without fabricating intermediate progress; Stop/terminal clears transient progress. Terminal outcome still follows the DB commit.

Native tool observations keep timing, tool name and status. Search phase observations and `memoryos.search.stage.duration` timers distinguish prefetch, semantic/keyword rewrite, source/time filters, embedding, hybrid IO, authorization, fusion, selection, expansion and classification. Concurrent tasks retain the parent observation context. Tags contain bounded stage/outcome values, never questions, document metadata or identity. An ordered handler strips sensitive tool values before start/error handlers; a filter strips result/payload/error text before stop. Content-bearing Embabel loggers are disabled and Spring AI content capture remains off.

Current source policy remains PUBLIC FILE. Restricted/provider principal ACL metadata and permission-aware top-k await the source authorization implementation. The opt-in grounded model corpus check and its recorded result are separate from fixture contracts; neither establishes full Onyx ranking parity or browser citation acceptance.
